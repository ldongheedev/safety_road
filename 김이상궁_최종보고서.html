2. 프로젝트 소개

2-1. 프로젝트 명

SafetyRoad — 공공시설 기반 안전 경로 추천 서비스

2-2. 주제 및 선정 이유

야간 보행 시 범죄 노출 위험, 어두운 골목 등 안전 취약 구간에 대한 사회적 우려가 높아지고 있습니다. 기존 네비게이션 서비스는 최단·최소 시간 경로만 제공하고 보행 안전성은 고려하지 않습니다. 본 프로젝트는 성남시 분당구 내 CCTV, 보안등, 경찰·치안 시설 등 공공 안전시설 데이터를 활용해 경로별 안전점수를 산출하고, 가장 안전한 보행 경로를 추천하는 서비스를 개발합니다.

2-3. 특장점

  • 실데이터 기반 안전점수 — 국가공공데이터포털의 CCTV 약 10,000건, 보안등 약 13,000건, 경찰/치안 35건을 실제 수집·저장하여 경로 안전성 계산에 활용
  • 복수 경로 비교 — T맵 API로 대로우선·최단·최소 시간 등 다양한 경로를 동시에 제시하고 경로마다 안전점수를 부여해 사용자가 직접 선택 가능
  • 실시간 위치 추적 — GPS 기반 현재 위치를 지도에 실시간 표시하고, 위험구역 진입 시 즉시 알림 배너 제공
  • 모바일 완전 지원 — 반응형 bottom sheet UI, 드래그 제스처, HTTPS(ngrok) 환경으로 스마트폰에서도 동일한 기능 제공
  • SOS 긴급 신고 버튼 — 긴급상황 발생 시 카운트다운 후 신고 가능한 FAB 버튼 제공

3-2. 스토리보드 — 화면 이동 경로

기능 흐름에 따른 화면 이동

[ 스토리보드 / 화면 흐름도 이미지 첨부 ]
  1. 메인 화면 — 지도 초기 표시, 현재 위치 자동 마커 표시

5-2. 구현 기능

① 안전 경로 추천 (담당: 김령균)

T맵 보행자 경로 API로 대로우선, 최단거리, 최소시간 등 복수 경로를 수신한 뒤, 각 경로의 Polyline 좌표에서 일정 간격으로 샘플 포인트를 추출합니다. 각 포인트의 반경 내 CCTV·보안등·경찰 시설 수를 PostGIS 공간 쿼리로 집계하고, 가중 평균으로 경로 전체 안전점수(0~100)를 산출합니다. 점수가 가장 높은 경로를 '추천 안전경로'로 표시합니다.

// 안전점수 계산 핵심 로직 (SafetyScoreService.java) double score = (cctvCount * 0.4 + lightCount * 0.4 + policeCount * 0.2) / samplePoints.size() * NORMALIZE_FACTOR; return Math.min(100.0, score);

② 공공데이터 수집 (담당: 이동희)

국가공공데이터포털 Open API를 통해 성남시 분당구 내 안전시설 데이터를 수집합니다. 수집된 데이터는 safety_facilities 테이블에 저장되며, PostGIS GEOMETRY(Point) 컬럼에 공간 인덱스를 적용해 반경 쿼리 성능을 확보합니다.

데이터 종류수집 건수출처

조도측정 보안등약 13,000건성남시 공공데이터
경찰/치안 시설35건공공데이터포털

③ 모바일 반응형 UI (담당: 이시우)

768px 이하 화면에서 좌측 패널이 화면 하단에서 올라오는 bottom sheet 형태로 전환됩니다. 패널 상단 핸들을 드래그해 패널을 접거나 펼칠 수 있으며, 드래그 중 지도가 함께 움직이는 현상은 non-passive touchmove 이벤트 리스너의 preventDefault()로 차단했습니다.

// 지도 이동 차단 — passive: false로 등록 handle.addEventListener('touchmove', (e) => { if (dragStartY.current === null) return; e.preventDefault(); // Kakao Maps 터치 이벤트 차단 const delta = e.touches[0].clientY - dragStartY.current; panelRef.current.style.maxHeight = `${newHeight}px`; }, { passive: false });

④ 실시간 위치 추적 (담당: 이동희)

navigator.geolocation.watchPosition()으로 사용자의 위치를 실시간 감지하고, Kakao Maps CustomOverlay로 파란 점 마커를 현재 위치에 표시합니다. Geolocation API는 HTTPS 환경에서만 동작하므로 ngrok 고정 도메인으로 모바일 테스트를 진행했습니다.

⑤ 위험구역 진입 알림 (담당: 이동희)

서버에서 HIGH 등급 위험구역 좌표를 앱 초기 로드 시 수신해두고, 위치 업데이트마다 현재 좌표가 위험구역 경계 내에 있는지 확인합니다. 진입이 감지되면 상단에 경고 배너를 표시하며, 동일 구역 30초 이내 중복 알림은 억제합니다.

⑥ 시설 마커 표시 (담당: 이시우)

사용자가 지도를 이동하거나 줌을 변경할 때마다(500ms 디바운스) 현재 뷰포트 경계를 서버에 전달합니다. 줌 레벨 5 이하(충분히 확대)일 때만 마커를 표시하며, CCTV는 파란색, 보안등은 노란색, 경찰/치안은 빨간색 원형 마커로 구분합니다.

8. 결과 및 고찰

8-1. 프로젝트 소감 및 느낀 점

김령균 (조장)

공간 데이터베이스(PostGIS)를 처음 사용해보며 일반 RDB와 다른 공간 쿼리의 개념을 익혔습니다. 안전점수 가중치 설계 시 CCTV, 보안등, 경찰 시설의 실질적 안전 기여도를 어떻게 수치화할지 고민하는 과정이 흥미로웠습니다. 팀 프로젝트에서 조장으로서 일정 관리의 중요성을 체감했습니다.

이동희

JPA를 제거하고 JdbcTemplate으로 전환하는 작업을 통해 SQL을 직접 다루며 데이터베이스를 더 깊이 이해할 수 있었습니다. 모바일 위치 권한을 위해 HTTPS 환경을 구축하는 과정에서 웹 보안 정책(Mixed Content, Geolocation 제약)에 대해 실질적으로 배웠습니다.

이시우

Kakao Maps API와 React를 결합하는 작업이 초반에 낯설었지만, 컴포넌트 분리와 훅(hook) 패턴을 적용하면서 구조가 잡혔습니다. 모바일 터치 이벤트가 브라우저의 기본 스크롤과 충돌하는 문제를 passive 이벤트 리스너 개념으로 해결하며 웹 이벤트 시스템을 깊이 이해했습니다.

8-2. 어려웠던 점 및 극복 사례

어려움극복 방법
JPA + Hibernate Spatial이 PostGIS와 충돌하여 서버 기동 불가 JPA 전체 제거 후 JdbcTemplate + 순수 SQL로 전환, 의존성 단순화
모바일 브라우저에서 Geolocation API 사용 불가 (HTTP 차단) ngrok 고정 도메인으로 HTTPS 터널 구축하여 위치 권한 획득
패널 드래그 시 지도도 함께 이동하는 버그 React 기본 이벤트(passive)를 우회해 DOM addEventListener에 { passive: false }로 직접 등록, preventDefault() 적용
경찰/치안 시설 안전점수 반영 안 됨 (항상 0건 집계) DB 실제 저장값('POLICE')과 코드 쿼리값('POLICE_BOX', 'DISTRICT_POLICE') 불일치 발견 후 통일
공공데이터 API 키 미확보로 일부 데이터 수집 불가 수집 가능한 키에 집중하고, 미확보 키는 기동 실패 방지를 위해 기본값(:) 처리
